# 运行指南

> 两种跑法：**本地 Python**（下面）或 **Docker**（末节）。
> 所有命令都在**项目根目录**（含 `pyproject.toml` 的那一层）执行——`.env` 与 SQLite 路径按当前目录解析。

---

## 一、三步跑通

**macOS / Linux**（`make` 是对 `python -m staguard` 的封装，等价命令见本节末）

```bash
make install                 # 建 .venv 并装依赖（Python 3.11+）
make gen-data                # 生成 14 天归档 + 7 个故障场景（固定种子，约 15s）
make run SCENARIO=S1         # 巡检 S1，报告写进 reports/S1/

cat reports/S1/run-*.md      # 看报告
```

**Windows**（没有 `make`，用仓库根目录的 `run.bat`）

```bat
.\run.bat                    :: 三步跑通：建环境 + 装依赖 + 生成数据 + 巡检 S1
.\run.bat inspect S5 http    :: 巡检指定场景、指定数据源
.\run.bat help               :: 全部子命令
```

> 前面那个 `.\` 不能省：PowerShell 出于安全考虑不会执行当前目录下的可执行文件，
> 直接敲 `run.bat` 会报「无法将"run.bat"项识别为 cmdlet」。CMD 里虽然可以省，
> 但统一写成 `.\run.bat` 两边都能用。

前置：装 Python 3.11+ 时**勾选 `Add python.exe to PATH`**。

`run.bat` 内部直接调用 `.venv\Scripts\python.exe`，所以**不需要激活虚拟环境**，也不受
PowerShell 执行策略限制；在 PowerShell 里执行 `.\run.bat` 即可。

> 不想用脚本时，两边也是同一条命令：`.venv/bin/python -m staguard run --scenario S1`（Windows 换成 `.\.venv\Scripts\python.exe -m staguard run --scenario S1`）。

## 二、配大模型 key（可选）

不配也能跑：AI 会自动降级为规则决策树归因，并在报告附录如实标注 `degraded=true`。

```bash
cp .env.example .env         # Windows: copy .env.example .env
```

在 `.env` 里填 `STAGUARD_LLM_API_KEY` 即可。默认用 DeepSeek 的 `deepseek-chat`，
换 `STAGUARD_LLM_PROVIDER` / `STAGUARD_LLM_MODEL` / `STAGUARD_LLM_BASE_URL` 可接别的模型。

## 三、Docker（两平台一致）

装了 Docker Desktop 就不需要 Python 环境：

```bash
docker compose up -d --build
docker compose down
```

起三个容器：模拟数据源（8090）、巡检 API（8080）、定时巡检（每 30 分钟，走 HTTP 通道），
报告与日志挂到本机的 `./reports`、`./logs`。

数据集在**镜像构建时**按固定种子生成，所以不需要先在本机跑 `make gen-data`：
从零 clone 的仓库直接 `up` 就能跑。

> **拉不到基础镜像时**（`python:3.12-slim` 走 Docker Hub，部分网络不可达）：
> 从可达的镜像站取下来再打上原标签即可，不用改 Docker 配置——
> `docker pull public.ecr.aws/docker/library/python:3.12-slim` 然后
> `docker tag public.ecr.aws/docker/library/python:3.12-slim python:3.12-slim`。
>
> **Linux 宿主上报告没落盘**：容器以 UID 10001 运行，而绑定挂载目录的属主是宿主用户，
> 写不进去时报告仍可从接口取到（该阶段只降级、不中断）。`sudo chown -R 10001 reports logs`
> 即可。macOS / Windows 的 Docker Desktop 会自动处理属主，不会遇到。

## 四、出问题先看这几条

| 现象 | 处理 |
| --- | --- |
| 直接敲 `run.bat` 报「无法将"run.bat"项识别为 cmdlet」 | PowerShell 不执行当前目录下的文件，加 `.\`：`.\run.bat` |
| `make` 不是内部或外部命令 | Windows 没有 make，用 `.\run.bat` |
| `python` 不是内部或外部命令 | 装 Python 时没勾 Add to PATH：重装勾上；或把 `python` 换成 `py -3.12` |
| 控制台中文、🔴 图标显示成方块 | 换 Windows Terminal（脚本已 `chcp 65001`）。**报告文件不受影响**——写文件一律显式 UTF-8 |
