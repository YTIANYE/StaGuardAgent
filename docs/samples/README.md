# 巡检报告样例

本目录存放**完整 AI 智能巡检输出报告示例**，由

```bash
make sample        # 等价于 staguard sample
```

生成，不是手工复制的产物。

## 文件名规则

```
<场景>-<AI 模式>.md

S1-rule-fallback.md   大模型不可用，走规则决策树兜底
S1-llm.md             调用真实大模型完成归因
```

把 AI 模式写进文件名，是为了让**两份报告可以并存**：
直接 `diff S1-rule-fallback.md S1-llm.md` 就能看出接入大模型到底带来了什么差异——
比口头说「接了模型效果更好」有说服力得多。

> `-llm` 版本需要配置 `STAGUARD_LLM_API_KEY`；未配置时系统自动降级，
> 并在报告的「附录 / AI 调用」一栏如实标注 `degraded=true` 与降级原因——
> **降级不隐藏，是这套系统的一条硬约束**。

## 先读哪一份

两条路径的**归因结论、评分、定级完全一致**（评测均为根因命中率 100% / 级别命中率 100% / 误报率 0%），
差别在于结论的**可执行性**。

- 想快速理解系统能力 → 读 [`S1-llm.md`](S1-llm.md)（依赖故障级联，结构最完整）；
- 想知道两版的差异到底在哪 → 读 [`AI对比说明.md`](AI对比说明.md)；
- 想做严谨的工程评审 → 建议直接 `diff S1-rule-fallback.md S1-llm.md`。


## 报告结构

每份报告固定八章，便于对照阅读：

1. **巡检概览** —— 窗口、覆盖范围、稳定性评分卡、逐项扣分依据、评分来源说明
2. **风险总结** —— AI 的风险总结、趋势判断与预测、自陈的证据不足之处
3. **异常清单** —— 按等级排序，含实测 / 基线 / 偏离 / 持续 / 起始时刻 / 级别理由
4. **多粒度统计** —— 服务维度（含无异常服务）与集群维度两张统计表
5. **根因分析** —— 按根因簇展开：信号规模、传播路径、规则假设、AI 结论、证据引用
6. **修复建议** —— 立即止血 / 短期加固 / 长期治理三档，带责任方
7. **稳定性趋势** —— 与上次巡检对比、复发识别、评分历史
8. **附录** —— 数据质量、规则命中统计、动态基线覆盖率、变更事件、阶段耗时、AI 调用元信息
