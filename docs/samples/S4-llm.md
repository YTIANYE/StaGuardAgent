本轮异常集中在 user-svc 及其上游 gateway：user-svc 两个实例业务错误率从 0.07% 飙升至 5.4%（持续 12 分钟），成功率跌至 98.6%，并沿 user-svc -> gateway 传导，gateway 三实例成功率同步下跌约 1.1 个百分点。user-svc 在异常起始前 3 分钟刚发布 v1.9.0（登录态校验逻辑重构，涉及 Session 解析路径），时间与链路上高度吻合，判定为变更引入的代码异常。

- **趋势判断**：持续恶化
  - 依据：user-svc 业务错误率序列 trend=rising，末值即为峰值 5.4%，成功率 trend=falling 且末值 98.6% 为区间最低；gateway 三实例成功率同样 falling 且末值接近区间最小值，异常在窗口末段仍在恶化，尚未见拐点。
  - 预测：若 v1.9.0 不回滚，按当前斜率外推，user-svc 业务错误率将在 30~60 分钟内继续抬升，gateway 成功率可能跌破 98%，错误预算消耗进一步扩大；回滚后预计 5~10 分钟内业务错误率回落至 0.1% 量级。
- **证据不足之处**：
  - 证据包未提供 user-svc 的日志/异常堆栈，无法直接确认 5.4% 业务错误率的具体错误码与 v1.9.0 改动的因果关系，仅依据发布时间（异常前 3 分钟）与链路位置推断

  - 历史相似事件（run-20260925-100000-S1，resource_bottleneck）相似度仅 0.04，且涉及 bank-channel/payment-svc 链路，与本簇服务集合不同，不构成复发证据

### 立即止血（本次窗口内）

- [CLUS-01] 对 v1.9.0 的 Session 解析路径改动做 diff 审查，重点核对登录态校验的异常分支与空值处理
- [CLUS-01] 在预发环境用线上流量回放验证 Session 解析路径，补齐登录态校验的单元/集成用例后再灰度

### 长期治理

- 建立发布与异常的时间关联看板：任何服务发布后 30 分钟内，自动比对该服务及其上游的成功率/业务错误率，触发即告警

- 为 gateway->user-svc->redis-session 链路配置端到端 SLO 与错误预算燃烧率告警，缩短从链路劣化到发现的时延
- 补齐 Session 解析路径的契约测试与故障注入用例，覆盖登录态失效、Session 缺失等边界场景
